## 先发现本地契约

写入前依次检查：

1. 当前目录及父目录中的 `AGENTS.md`、`CLAUDE.md` 或等价规则；
2. 知识库索引、入口页和目录说明；
3. frontmatter、命名、链接和日志格式；
4. Inbox、正式知识层、来源库和归档边界；
5. 当前工作树是否存在用户未提交修改。

让本地契约决定物理路径和写入流程。本 skill 只规定认知结构，不覆盖项目自身的知识生命周期。

## 查询顺序

若工作区已有知识层，按以下顺序查询：

1. 总索引；
2. 相关研究方向页；
3. 活跃研究问题页；
4. 综合页和来源摘要；
5. 必要时回到原始来源。

除非用户询问待处理线索，不把 Inbox 中的临时内容当作稳定结论。

找不到现有结构时，先报告缺失，再提出最小结构。不要未经确认创建大型目录体系。

## Capture 与 Ingest

### Capture

保存新材料、初步定位和待判断问题。它仍然是候选或过程记录。

### Ingest

把已核验内容编译进研究问题、证据关系、边界和判断变化。它意味着内容开始承担稳定知识责任。

不要把“保存文件”“写一篇文献笔记”自动解释为正式 ingest。

用户明确要求“加入知识库”时，仍先区分：

- 只保存来源；
- 建立来源笔记；
- 更新研究问题页；
- 正式 ingest。

如果语境已清楚且写入低风险，可以直接执行；涉及高价值判断时先展示更新提案。

## 写入决策

### 可以直接写入

- DOI、作者、年份、路径等已核验来源信息；
- 用户明确提供的研究问题和事实；
- 低风险链接修复；
- 已确认判断的格式化和关系维护；
- 按本地协议追加日志。

### 先生成更新提案

- 改变当前研究判断；
- 调整置信程度；
- 选择竞争解释；
- 重定义研究问题；
- 将作者解释写成稳定知识；
- 把材料认定为强反证或核心证据；
- 关闭重要不确定性。

更新提案至少标明：

```text
目标页面
原有判断
拟修改内容
来源与证据边界
Agent 推断
需要研究者决定的部分
```

## 默认 Markdown 结构

只有在工作区没有约定、且用户同意建立结构时，采用最小方案：

```text
research-knowledge/
├── index.md
├── inbox/
├── directions/
├── questions/
└── sources/
```

不要默认创建表格注册系统、编号体系、任务库、投稿库或版本库。

优先使用人类可读标题和双向链接。只有真实使用暴露出消歧、规模或自动化需求时，再引入 ID。

## 编辑与来源边界

- 把原始论文、数据、会议记录和用户文件视为 source of truth。
- 默认只读来源，除非用户明确要求整理或改写。
- 优先更新现有问题页，不为同一问题建立近义重复页。
- 保留用户已有修改，避免覆盖无关内容。
- 只修改当前任务必需的页面。
- 涉及移动、删除、发布、远程提交或不可逆操作时，复述影响并取得授权。
- 更新正式知识时同步维护索引、反向链接和本地要求的日志。

## 隐私

- 优先沉淀匿名化、流程化和可复用判断。
- 不为学生、同事、评审对象或合作方建立不必要的长期人物档案。
- 把会议意见与经验事实区分；只有完成任务所需的信息才进入稳定知识。
- 敏感来源页只提取研究推进所需的事实、任务、反馈和判断变化。

## 审计

定期检查：

- 孤立来源笔记；
- 只有支持证据的问题页；
- 长期未更新的判断；
- 证据层级与结论不匹配；
- 相同问题的重复页面；
- 已失效来源链接；
- 下一项证据需求过于宽泛；
- 本应由数据解决却持续堆积文献的未知；
- Inbox 内容被误用为稳定知识。

先提供审计建议，不默认大批量重写。
